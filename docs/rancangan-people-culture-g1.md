# Rancangan People & Culture Gelombang 1 (ditunda)

Status: **dibangun mulai 1 Oktober 2026** (owner: "kembali ke fitur"; sempat ditunda 30 September). Backend selesai: migrasi 106 (direktori, lokasi, izin) dan 107 (aset IT), tanpa data yang diimpor.

Isi dokumen: rancangan teknis untuk baris 1.1 (Direktori & struktur organisasi PFN) dan 1.2 (Aset IT PFN), disusun Claude sebagai Head People & Culture, IT Lead, dan IT Security atas delegasi owner. Rancangan awal dikritik oleh tiga peninjau independen (40 temuan). Setiap temuan diterapkan atau ditolak dengan alasan di Bagian 1, jadi **Bagian 1 mengikat** dan menggantikan Bagian 2 bila keduanya berbeda. Teks teknis sengaja dibiarkan dalam bahasa Inggris seperti saat diserahkan ke pembangun.

Saat dilanjutkan:
- Nomor migrasi diambil dari nomor bebas berikutnya saat dilanjutkan (103 dan 104 dipakai perbaikan tinjauan akhir program 4 divisi). Periksa `schema_migrations` sebelum mulai.
- File laporan perangkat PFN diambil ulang dari Google Sheets owner. Salinan kerja sementara sudah dihapus karena memuat 4 password WiFi.
- Tidak ada data yang diimpor tanpa persetujuan owner.

## Catatan pembangunan (1 Oktober 2026)

- **Aturan 3:** `CHECK (manager_id <> id)` tidak bisa dibuat di MySQL (error 3818, kolom AUTO_INCREMENT). Atasan diri sendiri dan lingkaran atasan ditolak di service, di dalam transaksi yang mengunci baris direktori perusahaan; dijaga tes di database asli.
- **Akun baru** hanya ditautkan ke baris direktori yang sudah ada (berdasarkan email). Akun tidak membuat baris baru, supaya catatan "akun belum ditinjau People & Culture" tetap bermakna.
- **Menu:** "Direktori" ada di Kerja Harian (semua karyawan boleh melihat kontak kerja), bukan di bagian People & Culture yang hanya tampil untuk divisi itu.
- **Uji data asli:** file laporan owner tidak diambil (butuh sesi owner). Gerbang memakai laporan sintetis dengan tata letak yang sama: 69 perangkat, 27 orang, kode perusahaan lain ditolak, kolom password tidak pernah dibaca, impor ulang 0 perubahan, 610 panggilan manajemen tanpa error. Semua di dalam transaksi yang dibatalkan; arsip Accurate tidak berubah.

## Bagian 1 — Rancangan revisi v2 (mengikat)


Supersedes Part 2 (spec v1) wherever they differ. The critique (3 critics, 40 issues) is folded in: every issue is either applied below or explicitly overruled here. Decisions by Claude as Head People & Culture / IT Lead / IT Security (owner delegated), 30 Sep 2026.

### A. Naming, collation, integrity
1. Table names: `people_directory` and `org_locations` (NOT `pc_…`, which is Procurement's Accurate mirror).
2. Both tables `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci` (same as users/departments/devices); no unicode_ci column; service trims names and trims+lowercases emails before every write. Test asserts the migration text.
3. Same-entity integrity in the DB: `UNIQUE (entity_id, id)` on both tables; manager and location as composite FKs `(entity_id, manager_id) → people_directory(entity_id, id)` and `(entity_id, location_id) → org_locations(entity_id, id)`; `CHECK (manager_id IS NULL OR manager_id <> id)`. Cycle check done inside a transaction holding `SELECT … FOR UPDATE` on the entity's directory rows (or `GET_LOCK('people_directory:<entity>')`).
4. Activity logs of directory/location/device-import writes are written with the SAME connection inside the transaction (INSERT INTO activity_logs via conn), not through the pool helper.

### B. Directory (1.1)
5. `people_directory`: id, entity_id, user_id NULL (UNIQUE(entity_id,user_id)), kind ENUM('employee','group_staff','excluded') DEFAULT 'employee', excluded_reason VARCHAR(160) NULL (CHECK kind<>'excluded' OR reason not null), full_name, name_key GENERATED (LOWER(TRIM(full_name))) STORED + KEY(entity_id,name_key), position, department_id NULL, manager_id NULL, work_email NULL (UNIQUE(entity_id,work_email)), work_phone NULL, location_id NULL, status ENUM('active','resigned'), resigned_on DATE NULL, resigned_on_source ENUM('entered','import','account') NULL, notes, created_by, updated_by, timestamps. No personal data.
6. For people WITH an app account, name, email and department are read from `users` (never a second copy): the row stores only kind, position, manager, phone, location, status/resign, notes. For people without an account, full_name/work_email/department_id live in the row.
7. Listing = active users of the entity (LEFT JOIN their row) + rows without user_id. Excluded rows are hidden from viewers, pickers, org chart, KPIs and escalations (visible to managers under an "Dikecualikan" chip). group_staff = works in this entity's app but employed by another group company: listed with a badge, pickable as manager, not counted. Headcount = active kind='employee' (users without a row count as employees) and the card also shows "N akun belum ditinjau People & Culture" for users with no row yet. The [UJI]/Test/shared admin accounts are marked excluded by P&C in the UI (not by a migration).
8. One matching function `ensurePersonForUser(conn, entityId, userId, actorId)` (link by email else insert, ON DUPLICATE KEY … LAST_INSERT_ID). Import/holder matching order: lowercased work email → exact name_key against users.name and people rows → otherwise new. A name-only match is shown "kemungkinan sama dengan <akun>" and defaults to LINK (never silently creates a duplicate). An email-less row with the same name_key = "sudah ada". users.controller create / email change runs the same link so a new account attaches to its row.
9. Work email: helper `workEmailDomains()` from GOOGLE_ALLOWED_DOMAIN (comma list, exact domain match after the last '@'); refuse when unset (WORK_EMAIL_DOMAINS_UNSET); always refuse gmail.com, googlemail.com, yahoo.com, yahoo.co.id, hotmail.com, outlook.com, live.com, icloud.com, ymail.com. `.env.example` → `prakasagroup.com,prakasafoods.com`. Tests as in the critique.
10. Resign: the UI requires a date. Import has no date → resigned_on = import date, resigned_on_source='import', shown "tanggal resign tidak ada di file". An app account that is deactivated/deleted counts as resigned for devices (source 'account'). Escalation episode uses COALESCE(resigned_on, row created day) — never NULL.
11. Permissions: `people.directory.view` for everyone in the entity shows work contact only (name, position, department, manager, work email/phone, location, "tanpa akun" badge); kind/excluded/resign details/notes only with `people.directory.manage` (P&C Supervisor/Head, super admin). Directory import has its own endpoints `/people/directory/import/{preview,apply}` guarded by people.directory.manage.
12. Approval by direct manager is NOT in wave 1 (program doc row 1.1 reworded): it comes with the onboarding/GA rework (wave 3/4), where only managers with an app account can approve and nobody approves their own request.
13. Management: the hrga provider (People & Culture) claims navPaths '/people/directory' and adds KPI `hrga_directory_unreviewed` (active accounts without a directory row; alert false) — keeps test/managementIntegration.test.js green.

### C. IT assets (moved from 2.3 into wave 1)
14. Status: add `damaged` to devices.status (broken, not at a vendor) — distinct from `repair` (at a vendor). Report mapping: Active→assigned, Spare→available, Damaged→damaged, Not Active→retired. IT can set the status directly (Aktif/Cadangan/Rusak/Tidak aktif, plus existing Perawatan/Perbaikan/Hilang/Dibuang) via a guarded endpoint: 'assigned' only with a holder; leaving 'assigned' closes the active assignment. New column `status_changed_at` (set on every status change, never ON UPDATE); providers' SERVICE_SINCE uses it; new escalation `it_device_damaged` (damaged > 14 days, episode = device id × 100000 + day of status_changed_at).
15. Holder = an assignment row, always: `device_assignments` gets `person_id` (people_directory, same entity) and `holder_label`; `assigned_to` becomes NULL-able; CHECK exactly one of assigned_to/person_id/holder_label. Imported Aktif devices get an active assignment row (so Kembalikan, reassignment and the resigned-holder check work). devices.current_assignee_id stays for app users; add holder_person_id/holder_label caches set by the same code path. Assignment create/return updated for person/label holders (409 only when an ACTIVE assignment exists).
16. Asset code is NOT unique (the real PFN data reuses 3 codes for 2 different laptops each): drop the global unique index, keep a normal index (entity_id, asset_code), preview warns "nomor aset dipakai N perangkat". Identity for idempotency: serial number (UNIQUE (entity_id, serial_number) when present, trimmed/uppercased); rows without a serial: composite (type, brand/model, asset code, holder) — shown "tanpa nomor seri, periksa manual". assetCode optional in zod and in the form; update() can set assetCode and deviceType.
17. Device department: department_id = the entity's People & Culture department (IT lives there) for imported/new devices, so the P&C Head's division view gets the KPIs/escalations.
18. Import: ONLY the owner's current device report layout ("Device Inventory" + hidden "User List"); the reference file is structure only, no reference-layout import. Explicit column-name mapping (the report's "User Name" = holder; never a regex that could drop it); any column whose header contains password/sandi/username/credential is never read. Server-side company check: the entity's report code = initials of the entity name (Prakasa Foods Nusantara → PFN), overridable by env IT_REPORT_ENTITY_CODE; apply rejects any other code. People rows of the same file are applied first in the same transaction, then holders resolve against them. Re-import: existing devices are never changed silently — preview lists field differences per row, IT may tick "perbarui" per row (explicit, logged). Summary rows skipped. Nothing imported by us without the owner's go-ahead.
19. Export: devices list exportable (xlsx/csv) through DataGrid, in the report's column order.
20. Types: add telephone, label_printer, fingerprint; one source of truth: backend constant + frontend model with Indonesian labels (test that they match the DB enum and each other); Brand/Model kept as one field "Merek / model" (stored in model, brand left empty) — no fake split.
21. itDashboard.controller summary() and aiReport() use req.user.entityId ONLY (currently honour req.query.entityId — cross-company read). Fix + test.
22. Dashboard: numbers labelled so they reconcile with the owner's report: "Karyawan (direktori)" with the unreviewed-account note; devices by status/type/location; Bermasalah = Rusak + Tidak aktif; tanpa nomor aset; garansi ≤ 60 hari; di tangan karyawan resign. No developer jargon ("diisi di Gelombang 2" → simply omit CCTV/bandwidth cards until those registers exist).
23. Management (providers/it.js): it_device_resigned_holder (episode per resign day; holder resigned per rule 10 > 3 days), it_device_damaged (rule 14), KPI it_devices_problematic; all scoped by d.department_id, no alarm while the entity has no devices.

### D. Gate
Tests for every rule above (mysql2 string numbers, collation text, domain helper, matching, excluded/headcount, status transitions, assignment CHECK, duplicate asset codes, serial identity, company-code check server-side, password/username columns ignored, re-import differences, dashboard scope, provider contract). Real-data gate: the owner's PFN rows imported INSIDE A ROLLED-BACK TRANSACTION (69 devices, 27 people): counts per action, duplicates warned, holders resolved/labelled, statuses, checksums unchanged. Headless (mocked API): IT Supervisor, P&C member, other-division member; desktop 1280 and mobile 390; no errors, no overflow.

## Bagian 2 — Rancangan awal v1 (dasar)


Author: Claude as Head People & Culture / IT Lead / IT Security, 30 Sep 2026. Read with docs/program-people-culture.md. Scope: entity 1 "Prakasa Foods Nusantara" (PFN) only; everything per entity.

### Decisions
1. **Directory = app users + people without an account.** One row per person in a new table `pc_people`; an app user's row is created the first time People & Culture edits them (the list shows every active app user of the entity even without a row, via a LEFT JOIN — no seeding). Fields: full name, position (jabatan), department, direct manager (another pc_people), work email (company domains only — `GOOGLE_ALLOWED_DOMAIN` list; personal gmail refused), work phone/extension, location, status aktif/resign with resign date, notes. No personal data (NIK, address, birth date, salary, bank). Rationale: devices and later onboarding/GA need people who have no app account (drivers, store staff).
2. **Who**: everyone in the entity may view the directory (work contacts) — new permission `people.directory.view` in COMMON_MEMBER; only People & Culture Supervisor/Head edit — `people.directory.manage`. Every change is logged in activity_logs (before/after of the changed fields). A person is never deleted: resign is a status.
3. **Locations**: new per-entity master `pc_locations` (name, kind office/store/warehouse/other, active). PFN: "PFN Office", "Alsut Office" (created by IT, or by the import when the user confirms). Rationale: devices, network, ISP and CCTV (wave 2) all hang on a location.
4. **Device status = the existing lifecycle, labelled like the report** (no second status): Aktif = assigned, Cadangan = available, Rusak = repair, Tidak aktif = retired, plus Perawatan = maintenance, Hilang = lost, Dibuang = disposed. The report's 4 statuses map exactly. Problematic (the report's "Problematic Devices") = Rusak + Tidak aktif.
5. **Holder** of a device: a directory person (`holder_person_id`) or a team label (`holder_label`, e.g. "Ops Team", "Semua karyawan") — not only app users. Assignments (`device_assignments`) get `person_id` and `holder_label`; `assigned_to` (users) becomes optional. Existing assignment flow keeps working for app users.
6. **Device fields added** (from the reference tab "02 - Users Device Inventory"): purchase_year, ram_gb, storage_gb (SSD), os_version, location_id, holder_person_id, holder_label. Asset code becomes optional (51 of 69 PFN devices have one) but unique per entity when present; serial number unique per entity when present. Types added: telephone, label_printer, fingerprint (report types map: Laptop→laptop, Monitor→monitor, Mobile Phone→smartphone, Tablet→tablet, Printer→printer, Printer Label/Printer Sticker Label→label_printer, Telephone→telephone, Fingerprint→fingerprint, Combo Touch/Speaker→peripheral; unknown→other with the original text in notes).
7. **Company scope** fixed in every IT controller touched (devices, assignments, handover/return, device logs, subscriptions, licenses, invoices, payments, vendors): entity = req.user.entityId, never body/query; every read/update/delete by id also checks entity_id; lists always filtered to the entity. Same for the HRGA controller's reads (full HRGA hardening is wave 3).
8. **Import** (IT Supervisor/Head, permission `device.manage`): Devices → "Impor dari Excel". The browser reads the .xlsx with the existing `read-excel-file` (sheet chosen by the user; recognises "Device Inventory" of the device report and "02 - Users Device Inventory" of the reference layout, header row detected by names), maps only known columns (never a password/username column), and posts JSON rows to `POST /it/devices/import/preview`. The server returns per row: action (baru / sudah ada — same serial or asset no in the entity / dilewati), mapped fields, issues (unknown type, unknown location, holder not found in the directory → will be created as a directory person? NO — shown as "pemakai belum ada di direktori", imported as holder_label), and the counts, including rows skipped as another company's (the Company column vs the chosen code; PFN preselected from the entity name's initials). The user picks the company code and confirms; `POST /it/devices/import/apply` re-validates the same payload server-side and inserts in one transaction: new devices only (existing ones are never changed), new locations only if the user ticked "buat lokasi baru". Summary rows (Active/Spare/Damaged/Not Active/TOTAL) are skipped. Logged with counts. Nothing is imported by Claude without the owner's go-ahead.
   The same import accepts the report's hidden "User List" / reference "01 - User List" for the directory (name, position, status, work email only; personal email domains dropped; only rows of the chosen company).
9. **IT dashboard (like the report)**: Total karyawan (active directory people), Total perangkat, Aktif, Bermasalah (Rusak + Tidak aktif), per status / per type / per location, devices without asset no., warranty ending in 60 days, devices held by resigned people. Wave 2 adds CCTV cameras and bandwidth; until then those cards say "diisi di Gelombang 2".
10. **Management (providers/it.js)**: new escalation `it_device_resigned_holder` — a device still held by a person resigned for more than 3 days (owner People & Culture/IT; sourceId = device id × 100000 + DATEDIFF(resigned_on,'2000-01-01') episode); new KPI `it_devices_problematic` (Rusak + Tidak aktif, sub: % dengan nomor aset). Existing `it_device_in_service` and `it_device_return_late` stay. No alarm while the entity has no devices.
